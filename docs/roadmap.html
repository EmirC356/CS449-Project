What the ESP32 is for

The laptop shows the code and the hints. The ESP32 is the learner's control over the AI and a quiet channel for offers, so help never interrupts the screen. A device that only repeats an on-screen click would be decorative.

“The physical object must represent a meaningful user choice, not merely replace a mouse click.” Handbook §3.2

Expert evaluation plan · Week 9

Follows the Week 2 lecture workflow. Expert evaluation finds likely breakdowns; it cannot show frequency or satisfaction, which is why the user study follows.

Evaluation question

Can a first-year student who has never seen the tool request, defer and silence AI help with the device, and understand which level of help they received, without the researcher’s help?

This is about learnability, so the main method is a cognitive walkthrough; a heuristic check and a domain review of the hint content support it.

1

Define

Question above. Evaluators: 3–5 CS201 / IF100 TAs.

2

Scope + scenario

“Your IF100 code fails its tests. Find the bug; get help if you need it, but you prefer to solve it yourself.” Do not name controls.

3

Inspect alone

Each TA works independently, records every issue with evidence and a screenshot, then answers the four walkthrough questions per step.

4

Consolidate

Merge duplicates, rate severity, fix the top one or two, re-check. That change is the PP2 design iteration.

SeverityCosmetic · Minor · Major · Critical, with a reason (frequency, recovery, outcome)
RecommendationWritten after the problem, never instead of it
Walkthrough questions for every step
  • Will the learner try to achieve the right effect?
  • Will they notice that the correct action is available (button, vibration, light)?
  • Will they connect the action with the effect they want?
  • After acting, will they see progress toward the goal?

Add one domain question for the TAs: does each hint stay within its level, or does it give away the fix too early?
